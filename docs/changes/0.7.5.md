# Cathode 0.7.5 — Cross-platform parity foundation

## What changed

- Established a canonical Android/desktop feature ledger.
- Added a required change-record format with desktop handoff instructions.
- Documented the desktop repository and packaging boundary.
- Added CI validation for the machine-readable ledger.

## Why

Android and desktop need equivalent product behavior without pretending their storage, media-session, permission, and packaging systems are interchangeable.

## Android implementation

- Android remains in `csanborndd17/cathode-android`.
- `docs/parity.json` records feature state and desktop equivalents.
- Android CI validates the ledger before testing and assembling the APK.
- No playback or user-data schema changed.

## Desktop parity instruction

- Create `csanborndd17/cathode-desktop` as a sibling repository.
- Start with Kotlin and Compose Multiplatform to reuse language, design tokens, and pure state logic.
- Do not copy Android MediaStore, services, notifications, WebView, or audio-effect APIs.
- Implement folder selection, a persistent index, OS media sessions, media keys, safe downloads, and resizable keyboard/mouse layouts.
- Copy the parity documents and update the desktop statuses as work lands.

## Data compatibility

Future exports need stable track identities based on normalized metadata plus file fingerprints. Android `content://` URIs and desktop absolute paths are not portable identifiers. Android 0.7.5 needs no migration.

## Verification

- JSON validation runs in GitHub Actions.
- Android unit tests and debug APK assembly must pass.

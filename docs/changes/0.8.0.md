# Cathode 0.8.0 — Interaction and Discover stabilization

## What changed

- Fixed Discover source WebViews being destroyed during source selection.
- Added visible source-load errors and retry/back controls.
- Added animated entry and exit for Now Playing, Settings, and Transmission Log.
- Library category and sort now return to Songs and Recent when Library is left or deliberately reopened from navigation.
- Reworked ambient particle timing so every motion channel joins seamlessly at the loop boundary.
- Added playlist-link library conversion to the planned feature ledger.

## Why

The first Release 7 field test exposed lifecycle, navigation-state, and animation continuity problems that CI compilation cannot detect.

## Android implementation

- Discover owns one WebView until the user closes that source or leaves the screen.
- Main-frame WebView errors replace the indefinite spinner with an actionable state.
- Full-screen overlays stay composed during animated exit.
- Home shortcuts may intentionally open a filtered Library; ordinary navigation clears that temporary view.

## Desktop parity instruction

- Use native desktop transitions with the same direction and reduced-motion behavior.
- Treat collection shortcuts as temporary Library views.
- Launch Discover sources through an isolated embedded browser only if the desktop runtime can enforce equivalent security; otherwise use the system browser.
- Implement playlist import through supported metadata APIs or explicit user authorization, never credential scraping.

## Data compatibility

No database migration is required. Playlist-link conversion is recorded as planned and stores no data yet.
